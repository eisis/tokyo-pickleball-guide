# コート掲載申請の仕組み

施設の運営者が自分でコートの掲載・更新を申し込み、サイト側が確認して公開する仕組み。

## 流れ（バリューチェーン順）

```
集客      トップ・ヘッダー・各コートの詳細ページ ─→ /owners/（運営者向けページ）
申し込み  /owners/ のフォーム（新規掲載 / 掲載中のコートの更新）
            └─ 写真は端末で縮めてから送る。入力は端末に一時保存
受付      /api/court-submit
            ├─ ロボット確認（Turnstile）・入力チェック
            ├─ GitHub に承認待ちの変更（PR）を作る：コートのファイル＋写真
            │    更新のときは、変わった項目の行だけを書き換える
            ├─ 受付台帳「コート掲載申請」タブに1行（連携相談・連携ステータスの列つき）
            ├─ info@ に通知メール（承認画面へのボタン付き。連携相談があれば件名に［連携相談あり］）
            └─ 申請者に自動返信
審査      GitHub の PR を開く → Vercel のプレビューで実際のページを確認
            ├─ 直したいところは「Files changed」から編集
            ├─ OK なら Merge → 本番に公開
            └─ 見送りなら Close
公開後    GitHub Actions（court-review.yml）
            ├─ Merge：公開を待って、申請者に掲載完了メール。台帳を「完了」に
            ├─ Close：台帳を「対応不要」に
            └─ 申請用のブランチを削除
連携      台帳の「連携相談」「連携ステータス」を見て、こちらから連絡して調整
```

## ファイル

| ファイル | 役割 |
|---|---|
| `src/pages/owners.astro` | 運営者向けページとフォーム |
| `api/_lib/court-form.js` | 項目・選択肢・連携相談メニュー・掲載基準の定義（項目を増やすときはここ） |
| `api/_lib/court-markdown.js` | 入力 ⇔ コートのファイルの変換、更新時の差分、地図リンクの読み取り、運営者確認 |
| `api/_lib/github.js` | PR の作成 |
| `api/_lib/common.js` | お問い合わせと共通の部品（台帳・メール・ロボット確認・暗号化） |
| `api/court-submit.js` | 受付 |
| `api/court-review.js` | 承認・見送りの通知（GitHub Actions から呼ばれる） |
| `.github/workflows/court-review.yml` | PR を閉じたときに動く |

## 設定値

| 置き場所 | 名前 | 中身 |
|---|---|---|
| Vercel の環境変数 | `GITHUB_SUBMIT_TOKEN` | このリポジトリだけに権限を絞った GitHub のトークン（Contents と Pull requests を読み書き） |
| Vercel の環境変数 | `SUBMIT_SECRET` | 自分で決めた長い合言葉 |
| GitHub の Actions シークレット | `SUBMIT_SECRET` | 上と同じ合言葉 |

`GITHUB_SUBMIT_TOKEN` がないときも受付はでき、台帳とメールにだけ残る（通知メールに「承認画面を作れませんでした」と出る）。

## 安全面

- リポジトリは公開なので、PR には申請者の名前・メール・電話・連携相談の中身を書かない。掲載完了メールの宛先は `SUBMIT_SECRET` で暗号化して PR の見えない場所に入れている
- 「運営者掲載」マーク（`ownerVerified: true`）は、運営者の立場で申し込み、かつメールのドメインが公式サイトと同じときだけ自動で付く。それ以外で本人と確認できたら、PR で `ownerVerified: true` を足す
- 本文に入った HTML は取り除く。記号を含む値は引用符を付けて書き出すので、ファイルの書式が壊れない（「,」入りの値が途中で切れる問題も起きない）

## 今後の広げ方

- イベント掲載も同じ流れ（フォーム → PR → Merge で公開 → 主催者にメール）にできる。`court-form.js` と同じ形の定義と、イベント用の変換を足す
- 空き状況の掲載が決まった施設は、コートのファイルに `availabilityUrl` を入れる（フォームからも入る）。自動取り込みを始めるときは `bookingSystem` ごとに取り込み処理を作る
- 有料プラン（上位表示・特集など）を始めるときは、コートのファイルに項目を足し、`/owners/` に案内を足す
